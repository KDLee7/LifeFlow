Objective

Learn how to update one item inside an array without affecting the other items.

Before This Lesson

I stored a single piece of state.

const [completed, setCompleted] = useState(false)
Problem

Every TaskCard shared the same value.

When I clicked one button:

Task 1 ✅
Task 2 ✅
Task 3 ✅

Everything changed.

Why Did That Happen?

There was only one completed value.

completed = false

Every TaskCard looked at that same value.

App
│
├── completed
│
├── TaskCard 1
├── TaskCard 2
└── TaskCard 3

Changing the state caused every TaskCard to update.

The Solution

Instead of storing one completed value, I stored the entire tasks array in state.

const [tasks, setTasks] = useState([
  {
    id: 1,
    title: "Learn React Components",
    completed: false,
  },
  {
    id: 2,
    title: "Build Navigation",
    completed: false,
  },
  {
    id: 3,
    title: "Learn CSS Flexbox",
    completed: false,
  }
])

Now every task owns its own completion status.

The Click Process

When I click a button:

Button Click
      │
      ▼
TaskCard
      │
      ▼
handleButtonClick(task.id)
      │
      ▼
App updates the tasks array
      │
      ▼
React re-renders the page
The Update Function
function handleButtonClick(id) {
  setTasks(
    tasks.map((task) => {
      if (task.id === id) {
        return {
          ...task,
          completed: !task.completed,
        }
      }

      return task
    })
  )
}
Breaking It Down
Step 1
setTasks(...)

Tell React I want to replace the tasks array.

Step 2
tasks.map(...)

Loop through every task.

Step 3
if (task.id === id)

Ask:

"Is this the task the user clicked?"

If yes, update it.

If no, leave it alone.

Step 4
return {
  ...task,
  completed: !task.completed
}

Copy the entire task.

Only change one property.

Everything else stays exactly the same.

Step 5
return task

Every task that wasn't clicked stays unchanged.

The Spread Operator
...task

Copies every property.

Example:

Original:

{
  id: 2,
  title: "Build Navigation",
  completed: false
}

New copy:

{
  ...task,
  completed: true
}

Result:

{
  id: 2,
  title: "Build Navigation",
  completed: true
}

Everything else remains unchanged.

Immutable Updates

React prefers creating new objects instead of changing existing ones.

Instead of doing this:

task.completed = true

(which changes the original object)

I create a new object:

return {
  ...task,
  completed: true
}

This is called an immutable update.

Data Flow

        │
        ▼

        │
        ▼
App receives ID
        │
        ▼
tasks.map() creates a new array
        │
        ▼
One task is updated
        │
        ▼
setTasks()
        │
        ▼
React updates the screen
Why React Does It This Way

React compares:

Old State

↓

New State

If something changed, React automatically updates the UI.

I never manually change the HTML.

I only update the data.

Key Takeaways
State should represent my application's data.
Each task owns its own properties.
Use IDs to identify the correct object.
Use .map() to create a new array.
Update only the object that changed.
React automatically updates the interface.
Things to Remember

✅ Store collections in state.

✅ Never modify the original object.

✅ Use the spread operator to copy objects.

✅ React updates the UI when state changes.
